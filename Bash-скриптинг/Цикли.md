### 1. Бізнес-контекст: Навіщо це потрібно?

Уяви задачу: до вашої компанії прийшло 50 нових розробників. Тобі як DevOps Engineer потрібно створити для кожного з них обліковий запис на Linux-сервері, згенерувати пароль і створити домашню директорію.

Робити це руками через `useradd` 50 разів — це марна трата часу і гарантована помилка через втому. За допомогою циклу ти пишеш код один раз, згодовуєш йому список із 50 імен, і сервер виконує всю роботу за 2 секунди. Цикли — це інструмент масового ураження рутини.

### 2. Анатомія та Архітектура (Як працюють цикли)

У Bash є два головні типи циклів. Вони вирішують різні архітектурні задачі.

**Цикл FOR (Працює зі списками):**

Використовується, коли ти **точно знаєш**, скільки разів треба виконати дію (наприклад, пройтися по списку з 5 серверів або 10 файлів).

Оболонка бере перший елемент зі списку, кладе його в тимчасову змінну, виконує блок коду, потім бере другий елемент, і так до кінця списку.

Bash

```
#!/bin/bash
for SERVER in "web1" "web2" "db1"
do
    echo "Підключення до сервера: $SERVER"
done
```

**Цикл WHILE (Працює з умовами та файлами):**

Використовується, коли ти **не знаєш** точної кількості кроків. Цикл крутиться доти, доки виконується певна умова. У DevOps `while` найчастіше використовують для того, щоб читати конфігураційні файли або логи рядок за рядком.

Bash

```
#!/bin/bash
COUNTER=1
while [ $COUNTER -le 3 ]
do
    echo "Спроба перезапуску: $COUNTER"
    ((COUNTER++))
done
```

### 3. Типові помилки (Анти-патерни)

1. **Нескінченний цикл (Infinite Loop):** Якщо у циклі `while` ти забудеш написати команду, яка змінює умову (наприклад, забудеш збільшити лічильник `COUNTER`), цикл буде крутитися вічно, з'їсть 100% процесора (CPU) і сервер "зависне". Зупинити такий скрипт можна лише комбінацією `Ctrl+C` у терміналі.
    
2. **Пробіли у списках для `for`:** Якщо змінна списку містить пробіли, і ти не візьмеш її в подвійні лапки, Bash розіб'є один елемент на кілька. Наприклад, файл `my backup.txt` цикл сприйме як два різні файли: `my` та `backup.txt`.
    

### 4. Тренувальна співбесіда

**Junior:** Чим принципово відрізняється цикл `for` від циклу `while`? В яких випадках ти використаєш кожен із них?

- _Сильна відповідь:_ Цикл `for` ідеальний для ітерації по готових колекціях (списки файлів, масиви IP-адрес). Цикл `while` краще підходить для подій, що тривають у часі (наприклад, "чекати, поки сервіс не підніметься") або для порядкового читання великих текстових файлів.
    

**Middle:** Як у Bash-скрипті прочитати текстовий файл рядок за рядком, щоб кожен рядок можна було обробити як окрему змінну?

- _Сильна відповідь:_ Найкраща і найбезпечніша практика — використати цикл `while` у комбінації з командою `read` та перенаправленням вводу. Синтаксис виглядає так: `while read -r LINE; do ... done < file.txt`.
