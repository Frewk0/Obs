 **Логічні умови `if/else` та перевірки файлової системи у Bash.**

### 1. Бізнес-контекст: Навіщо це потрібно?

Скрипт, який просто виконує команди згори донизу — це небезпечний скрипт.

Уяви наш `cleaner.sh` із минулого завдання (`> $1/error.log`). Що станеться, якщо ти випадково запустиш його і передаш шлях до папки, якої не існує (наприклад, `/var/loog`)? Скрипт просто створить порожній файл `error.log` у якійсь випадковій неіснуючій директорії або видасть некрасиву системну помилку.

У DevOps діє правило: **"Ніколи не довіряй вхідним даним"**. Перш ніж щось видалити, змінити або перезапустити, твій скрипт повинен самостійно перевірити: "А чи існує цей файл?", "А чи запустив мене адміністратор?", "А чи передали мені взагалі хоч якісь аргументи?".

### 2. Анатомія та Архітектура (Як працюють умови)

У Bash логічні умови будуються навколо команди `[ ]` (це не просто дужки, під капотом Linux це реальна системна команда `test`).

**Базовий синтаксис:**

Bash

```
if [ умова ]; then
    # Команди, які виконаються, якщо умова ПРАВДИВА (True)
else
    # Команди, які виконаються, якщо умова ХИБНА (False)
fi
```

_(Слово `fi` — це `if` навпаки, воно закриває блок логіки)._

**DevOps-арсенал перевірок (Прапорці):**

- `-d шлях` — перевіряє, чи існує така **д**иректорія (Directory).
    
- `-f шлях` — перевіряє, чи існує такий **ф**айл (File).
    
- `-z рядок` — перевіряє, чи є рядок або змінна порожніми (Zero length).
    
- `-eq`, `-ne`, `-gt`, `-lt` — математичні порівняння (Equal, Not Equal, Greater Than, Less Than).
    

### 3. Демонстраційні приклади

**Приклад 1 (Beginner): Базова логіка**

Bash

```
#!/bin/bash
USER_ROLE="DevOps"

if [ "$USER_ROLE" == "DevOps" ]; then
    echo "Доступ дозволено."
else
    echo "Доступ заборонено!"
fi
```

**Приклад 2 (Middle): Перевірка існування файлу перед дією**

Bash

```
#!/bin/bash
CONFIG="/etc/nginx/nginx.conf"

if [ -f "$CONFIG" ]; then
    echo "Файл конфігурації знайдено. Перезапускаю Nginx..."
    # systemctl restart nginx
else
    echo "Помилка: Файл $CONFIG не існує! Зупинка скрипта."
fi
```

**Приклад 3 (Production): Захист від запуску без прав root**

Це золотий стандарт для скриптів, які змінюють систему.

Bash

```
#!/bin/bash
if [ "$(whoami)" != "root" ]; then
    echo "CRITICAL: Цей скрипт потрібно запускати через sudo!"
    exit 1 # Команда exit зупиняє скрипт. 1 означає, що сталася помилка.
fi
echo "Запуск із правами адміністратора..."
```

### 4. Типові помилки (Анти-патерни)

1. **Забуті пробіли біля дужок:**
    
    - ❌ `if["$VAR" == "test"]` — Викличе помилку `command not found`.
        
    - ✅ `if [ "$VAR" == "test" ]` — Обов'язково потрібні пробіли після `[` та перед `]`.
        
2. **Відсутність подвійних лапок навколо змінних:**
    
    - ❌ `if [ $1 == "start" ]; then` — Якщо користувач запустить скрипт взагалі без аргументів, змінна `$1` буде порожньою, і Bash побачить команду `if [ == "start" ]`, що призведе до синтаксичної аварії (Syntax Error).
        
    - ✅ `if [ "$1" == "start" ]; then` — Якщо змінна порожня, Bash побачить `if [ "" == "start" ]` і спокійно відпрацює логіку (умова хибна).
        

### 5. Тренувальна співбесіда

**Junior:** Що означає команда `exit 1` у Bash-скрипті, і чим вона відрізняється від `exit 0`?

- _Сильна відповідь:_ Команда `exit` перериває виконання всього скрипта і повертає ядру Linux так званий Exit Status (код завершення). `exit 0` означає, що скрипт відпрацював успішно і без помилок. Будь-яке число від 1 до 255 (наприклад, `exit 1`) сигналізує операційній системі або іншим скриптам, що сталася аварія чи помилка.
    

**Middle:** Навіщо в сучасних скриптах замість одинарних дужок `[ ]` часто використовують подвійні `[[ ]]`?

- _Сильна відповідь:_ Подвійні дужки `[[ ]]` — це розширена, більш сучасна і безпечна версія команди `test` у Bash. Вони розумніші: не вимагають обов'язкового взяття змінних у подвійні лапки, не ламаються через порожні змінні та підтримують регулярні вирази (Regex) за допомогою оператора `=~`.
