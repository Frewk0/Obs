
### Bash-скриптинг — Фундаментальна документація

**1. Анатомія скрипта (Shebang)**

Скрипт — це звичайний текстовий файл. ОС Linux не зважає на розширення файлів (навіть якщо це `.sh`). Щоб система зрозуміла, що цей текст є програмою, перший рядок файлу завжди повинен містити "магічне число" — **Shebang**:

Bash

```
#!/bin/bash
```

Цей рядок вказує ядру операційної системи абсолютний шлях до інтерпретатора, який має прочитати і виконати наступний код.

**2. Робота зі змінними**

Bash має надзвичайно строгий синтаксис щодо пробілів під час роботи зі змінними:

- **Створення змінної:** Строго БЕЗ пробілів навколо знака дорівнює.
    
    Bash
    
    ```
    ROLE="DevOps"      # Правильно
    ROLE = "DevOps"    # КРИТИЧНА ПОМИЛКА (Bash шукатиме команду з назвою ROLE)
    ```
    
- **Використання змінної:** Щоб звернутися до значення змінної, перед її назвою ставиться знак долара `$`. Найкраща практика — завжди брати змінні у подвійні лапки, щоб уникнути розбиття тексту на частини, якщо він містить пробіли.
    
    Bash
    
    ```
    echo "My role is $ROLE"
    ```
    

**3. Підстановка команд (Command Substitution)**

Дуже часто скрипту потрібно виконати системну команду (наприклад, `whoami`, `date`, `pwd`) і вставити її результат прямо в текст або зберегти у змінну. Для цього використовується синтаксис `$(команда)`:

Bash

```
echo "System initialization started by user: $(whoami)"
```

Під час виконання ядро спочатку запустить команду всередині дужок, отримає її результат, і лише потім виведе фінальний рядок.

**4. Життєвий цикл: Від тексту до процесу**

Щоб щойно написаний скрипт запрацював, потрібно виконати два обов'язкові кроки у терміналі:

- **Крок А: Надання прав на виконання.** За замовчуванням файли не створюються як виконувані. Їм потрібно додати право `Execute` (`x`):
    
    Bash
    
    ```
    chmod +x script.sh
    ```
    
- **Крок Б: Безпечний запуск.** З міркувань безпеки Linux не запускає програми з поточної папки, якщо ти просто введеш їхню назву. Потрібно явно вказати системі шлях (крапка означає "поточна директорія"):
    
    Bash
    
    ```
    ./script.sh
    ```
    

**5. Передача аргументів (Позиційні параметри)**

Скрипти вміють приймати зовнішні дані прямо під час запуску (наприклад: `./script.sh /var/log`). Всередині скрипта ці дані доступні через спеціальні змінні:

- `$0` — зберігає те, як саме був запущений скрипт (наприклад, `./script.sh`).
    
- `$1` — зберігає перший переданий аргумент (`/var/log`).
    
- `$2`, `$3` і так далі — зберігають наступні аргументи по черзі.
    

### 1. Механіка позиційних аргументів

Коли ти запускаєш будь-яку команду в терміналі, оболонка Bash спочатку читає весь твій рядок і розбиває його на частини, використовуючи пробіли як розділителі. Кожній такій частині система автоматично присвоює порядковий номер — це і є **позиційні змінні**.

Якщо ти вводиш у терміналі:

`./myscript.sh start --force`

Оболонка розкладе це у своїй пам'яті так:

- `$0` — це завжди назва самої програми або скрипта (у цьому випадку `./myscript.sh`).
    
- `$1` — це перше слово після пробілу (у цьому випадку `start`).
    
- `$2` — це друге слово після пробілу (у цьому випадку `--force`).
    

Всередині файлу `myscript.sh` ти можеш просто написати `$1`, і Bash автоматично підставить туди слово `start`, або будь-яке інше слово, яке користувач вирішить ввести під час запуску. Тобі не потрібно заздалегідь знати, що саме введе користувач.

### 2. Як передати системну директорію?

Шлях до директорії (наприклад, `/etc` або `/var/log`) — це для оболонки Bash просто звичайний текстовий рядок.

Коли ти хочеш, щоб твій майбутній скрипт `sysinfo.sh` працював саме з папкою `/etc`, ти здійснюєш його запуск у такому форматі:

`./sysinfo.sh /etc`

**Що відбувається під капотом (Покроково):**

1. Ядро бачить команду і розбиває рядок по пробілу.
    
2. Воно бере рядок `/etc` і непомітно кладе його в системну змінну `$1`.
    
3. Скрипт починає виконуватися рядок за рядком зверху вниз.
    
4. Коли інтерпретатор доходить до рядка з кодом `du -sh $1`, він підставляє значення змінної.
    
5. Фактично, в пам'яті сервер формує і виконує команду `du -sh /etc`.
    

Якби завтра тобі знадобилося перевірити іншу папку, ти б просто написав `./sysinfo.sh /var/log`. Змінна `$1` стала б дорівнювати `/var/log`, і скрипт автоматично перевірив би її. Тобі не треба відкривати редактор `nano` і переписувати код скрипта для кожної нової папки. Це і є фундамент інфраструктурної автоматизації — код пишеться один раз, а використовується з різними даними тисячі разів.


### Типові помилки та Дебаг (Як не зламати Production)

Найбільший страх інженера — запустити скрипт видалення старих бекапів `rm -rf ${BACKUP_DIR}/*`, коли змінна `BACKUP_DIR` випадково виявилася порожньою. Уяви, на що перетвориться команда: `rm -rf /*`. Це смерть сервера.

**DevOps Best Practices (Strict Mode):** Завжди починай свої production-скрипти з цього рядка (відразу після shebang): `set -e`

- Що це робить: Якщо **будь-яка** команда у твоєму скрипті завершиться з помилкою (код не 0), скрипт **миттєво зупиниться**. Він не піде виконувати наступні рядки. Це рятує життя серверам.
    

**Як дебажити скрипт:** Якщо скрипт робить якусь магію, і ти не розумієш де він ламається, запускай його з параметром трасування: `bash -x ./script.sh` Це виведе на екран кожен рядок коду і значення кожної змінної _перед_ тим, як її виконати.


### 1. Фігурні дужки `{ }` — Межі змінної (Parameter Expansion)

Коли ти пишеш `$VAR`, Bash намагається знайти змінну. Але якщо відразу після імені змінної йде текст, Bash може заплутатися. **Фігурні дужки чітко вказують Bash, де починається і де закінчується ім'я змінної.**

  

**Анти-приклад (Чому стається помилка):**

Уяви, що ти пишеш скрипт для бекапу. Ти хочеш створити файл з іменем бази даних і додати слово `_backup`.

  

Bash

```
DB_NAME="users"
echo "Створюю файл $DB_NAME_backup.sql"
```

_Що відбудеться:_ Bash подумає, що ти хочеш вивести змінну з назвою `DB_NAME_backup`. Оскільки ти такої змінної не створював, вона порожня. Скрипт виведе: `Створюю файл .sql`. Це катастрофа для автоматизації!

  

**Правильний приклад (Як рятують фігурні дужки):**

  

Bash

```
DB_NAME="users"
echo "Створюю файл ${DB_NAME}_backup.sql"
```

_Що відбудеться:_ Bash бачить `${DB_NAME}`, бере значення `users`, а далі спокійно приклеює текст. Вивід: `Створюю файл users_backup.sql`.

  

> **DevOps Best Practice:** Завжди використовуй `${VAR}` замість `$VAR`. Це правило хорошого тону (як відступи в Python), яке вбереже тебе від годин дебагу. Крім того, фігурні дужки дозволяють робити магію: наприклад, `${VAR:-default}` підставить слово "default", якщо змінна порожня.
> 
>   

### 2. Круглі дужки зі знаком долара `$()` — Підстановка команди (Command Substitution)

Якщо фігурні дужки працюють зі _змінними_, то круглі — працюють із **командами**.

Конструкція `$()` каже Bash: _"Зупинись. Виконай команду, яка написана всередині цих дужок. Візьми текст, який ця команда вивела б на екран, і підстав його сюди"_.

  

**Приклад із життя:**

Тобі треба зберегти поточну дату у змінну, щоб потім додати її до назви архіву.

  

Bash

```
CURRENT_TIME=$(date +%Y-%m-%d)
echo "Сьогодні: ${CURRENT_TIME}"
```

_Що відбувається під капотом:_ Bash спочатку запускає утиліту `date`. Вона генерує текст `2026-08-20`. Bash перехоплює цей текст і записує його у змінну `CURRENT_TIME`.

  

_(До речі, у старих скриптах ти можеш побачити зворотні апострофи: `` `date` ``. Це застарілий синтаксис, `$()` набагато кращий, бо його легше читати і можна вкладати один в один)._

  

### 3. Круглі дужки без долара `( )` — Ізоляція (Subshell)

Коли ти береш команди просто в круглі дужки `( команда1; команда2 )`, Bash створює для них **окремий, ізольований дочірній процес (Subshell)**.

  

**Навіщо це треба?** Щоб не "забруднити" поточний термінал.

Уяви, що тобі треба зайти в іншу папку, зробити там архів і повернутися назад.

  

Bash

```
# Без Subshell (ти зміниш папку для всього скрипта, що може щось зламати далі):
cd /var/log/
tar -czf logs.tar.gz *.log
cd - 

# Із Subshell (безпечно і елегантно):
(cd /var/log/ && tar -czf logs.tar.gz *.log)
```

У другому варіанті перехід у папку `cd /var/log/` відбудеться тільки всередині тимчасової "бульбашки" (Subshell). Коли дужка закриється, бульбашка зникне, а твій головний скрипт навіть не помітить, що хтось кудись переходив.

  

### Коротке резюме (Шпаргалка)

- **`[[ ]]`** (Квадратні) — Перевірка логічних умов (якщо `A == B`).
    
      
    
- **`${ }`** (Фігурні) — Безпечне читання змінних.
    
      
    
- **`$( )`** (Круглі з `$`) — Виконати команду і забрати її результат.
    
      
    
- **`( )`** (Круглі без `$`) — Виконати команди в ізольованому процесі.
