### 1. Де побачити, що OOM Killer дійсно когось убив (Логи)

Коли на сервері раптово зникає процес (наприклад, падає вебсервер або база даних), перше, що робить DevOps — перевіряє системні логи ядра. Саме ядро (Kernel) викликає OOM Killer, коли йому критично не вистачає RAM.

- **Команда 1 (Логи ядра в реальному часі):**
    
    Bash
    
    ```
    dmesg | grep -i oom
    ```
    
    Якщо OOM Killer спрацьовував, ти побачиш рядок на зразок: `Out of memory: Killed process 1234 (postgres)`.
    
- **Команда 2 (Історія в системних логах):**
    
    Bash
    
    ```
    grep -i oom /var/log/syslog
    ```
    
    _(Для систем на базі RedHat/CentOS шлях буде `/var/log/messages`)._
    

### 2. Як система обирає жертву (Рейтинг у /proc)

Як я казав раніше, для кожного запущеного процесу ядро створює папку в директорії `/proc/<PID>/`. Саме там лежать два ключові файли, які розкривають усю логіку OOM Killer-а.

- **Файл `oom_score` (Поточний вирок):**
    
    У цьому файлі зберігається динамічне число (зазвичай від 0 до 1000). Чим більше пам'яті споживає процес, тим вищий його бал. OOM Killer — дуже простий механізм. Він просто сканує всі процеси, знаходить той, у якого значення `oom_score` найбільше, і вбиває його.
    
    Bash
    
    ```
    # Подивитися рейтинг процесу з PID 1234
    cat /proc/1234/oom_score
    ```
    

### 3. Як DevOps захищає критичні процеси (oom_score_adj)

Тут починається справжня інженерія. Уяви, що в тебе на сервері працює критична база даних і якийсь другорядний скрипт. Якщо пам'ять закінчиться, ти хочеш, щоб вмер другорядний скрипт, а не БД.

Для цього існує файл `oom_score_adj` (Adjust — коригування). Ти можеш штучно змінити рейтинг процесу, додавши або віднявши від нього значення (від -1000 до +1000). Ядро додасть це значення до базового рейтингу.

- **Екстремальний захист (`-1000`):** Якщо записати у файл значення `-1000`, ядро зробить цей процес повністю "безсмертним". OOM Killer буде ігнорувати його за будь-яких умов.
    
- **Як це зробити практично (потрібні права root):**
    
    Bash
    
    ```
    # Зробити процес з PID 1234 недоторканним для OOM Killer
    echo -1000 | sudo tee /proc/1234/oom_score_adj
    ```
