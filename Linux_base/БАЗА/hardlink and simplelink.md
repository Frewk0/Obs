### 1. Фундамент: Що таке Inode?

Щоб зрозуміти лінки, треба повністю перемкнути мислення і забути те, як працюють файли в інших операційних системах. У Linux **файли не мають імен**.

Для ядра системи файл — це просто структура даних на жорсткому диску, яка називається **Inode** (Index Node). Inode має унікальний числовий номер і зберігає всю метаінформацію: розмір, права доступу, власника та мапу того, в яких саме фізичних секторах диска лежать байти твоєї інформації.

А те, що ми називаємо "іменем файлу" (наприклад, `config.yaml`) — це лише зручна для людей текстова етикетка в директорії, яка вказує на цей Inode.

### 2. Hard Link (Жорстке посилання)

Жорстке посилання — це створення **ще однієї етикетки** для того ж самого Inode.

- **Під капотом:** Якщо оригінальний файл `A` має Inode №1050, і ти створюєш для нього Hard Link `B`, файл `B` також отримує Inode №1050.
    
- **Особливості:** Оригінал і посилання стають абсолютно рівноправними. Між ними немає різниці. Якщо ти видалиш оригінальний файл `A`, дані на диску не зникнуть, оскільки етикетка `B` продовжує вказувати на цей Inode. Дані стираються фізично лише тоді, коли видалено **усі** жорсткі посилання.
    
- **Жорсткі обмеження:** Не можна створювати Hard Links для директорій (щоб ядро не потрапило в нескінченний цикл при скануванні) і не можна створювати їх між різними дисковими розділами (оскільки на різних дисках своя незалежна нумерація Inodes).
    

### 3. Soft / Symbolic Link (Символічне посилання або Symlink)

Це аналог звичного "ярлика", але інтегрований на рівні ядра.

- **Під капотом:** Це **абсолютно новий файл** із власним, унікальним номером Inode. Але замість корисних даних, у його тілі лежить просто текстовий рядок — шлях до оригінального файлу.
    
- **Особливості:** Якщо ти видалиш оригінальний файл, Symlink залишиться існувати, але стане "битим" (червоним у терміналі), оскільки текстовий шлях тепер веде в нікуди.
    
- **Переваги:** Немає жодних обмежень. Можна лінкувати цілі директорії, можна лінкувати файли на інших серверах чи змонтованих флешках, можна навіть створити лінк на файл, якого ще не існує.
    

### 4. Візуалізація архітектури

Plaintext

```
[ Фізичні дані на диску ] <--- (Inode: 1050) <--- "original.txt"
                                   ^
                                   |------------- "hardlink.txt"

[ Текст: "/original.txt" ] <--- (Inode: 8022) <--- "symlink.txt"
```
### Команда `ln` (Link) — Архітектор зв'язків

**Призначення:** Створення жорстких (hard) та символічних (soft/symbolic) посилань між файлами та директоріями.

**Що відбувається "під капотом":** На відміну від команди `cp` (copy), яка бере байти з жорсткого диска і фізично дублює їх в інше місце, витрачаючи вільний простір, команда `ln` не копіює корисні дані взагалі. Вона працює виключно з метаданими та таблицями імен. Коли ти виконуєш базову команду `ln`, вона робить системний виклик `link()`, наказуючи файловій системі просто додати ще один запис у таблицю директорії, який вказуватиме на той самий фізичний сектор диска (Inode).

**Ключові параметри (DevOps арсенал):**

- `ln <оригінал> <назва_посилання>`
    
    - _Дія:_ Створює жорстке посилання (Hard Link).
        
    - _Обмеження:_ Працює **тільки для файлів** (не можна злінкувати папку) і **тільки в межах одного дискового розділу** (не можна зробити хардлінк з диска `/dev/sda` на флешку `/dev/sdb`).
        
- `ln -s <оригінал> <назва_посилання>`
    
    - _Дія:_ Створює символічне посилання (Soft Link / Symlink). Додавання прапорця `-s` змінює системний виклик на `symlink()`.
        
    - _Можливості:_ Універсальна зброя. Можна лінкувати цілі директорії, можна лінкувати файли на інших змонтованих дисках.
        
- `ln -f` (force) або `ln -sf`
    
    - _Дія:_ Примусове перезаписування. Якщо файл `назва_посилання` вже існує, команда мовчки видалить його і створить лінк наново. Дуже часто використовується в Bash-скриптах під час автоматизації деплою нових версій застосунків.
        

### Як відрізнити лінки (Дебаг через `ls -l`)

Коли ти створюєш посилання, тобі потрібно вміти їх розпізнавати у списку файлів. Утиліта `ls -l` дає для цього всі підказки:

**1. Символічне посилання (Soft Link)** Воно буквально кричить про те, що воно посилання.

- Перший символ у стовпці прав доступу буде літерою `l` (link), наприклад: `lrwxrwxrwx`.
    
- У кінці рядка ти чітко побачиш стрілочку, яка показує маршрут: `softlink.txt -> original.txt`.
    

**2. Жорстке посилання (Hard Link)** Воно маскується. Візуально хардлінк виглядає як абсолютно звичайний файл.

- Перший символ прав доступу буде дефісом `-` (звичайний файл).
    
- Жодних стрілочок у кінці рядка немає.
    
- _Як його знайти?_ Дивитися на колонку **"Кількість посилань"** (це перша цифра одразу після прав доступу `-rw-r--r-- 1`). У звичайного файлу, який ти щойно створив, там стоїть `1`. Як тільки ти створиш для нього хардлінк, ця цифра зміниться на `2` (і для оригіналу, і для посилання). Щоб довести, що це один і той самий файл, потрібно використати команду `ls -li`, щоб порівняти їхні номери Inodes.
